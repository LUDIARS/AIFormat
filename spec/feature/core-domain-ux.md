# コアドメイン UX 定義と契約受け入れサンプル

neco の 2026-09-07 指示: コアドメインには独立した UX 定義書を作り、Anatomia と
Praeforma が同じ資料を参照する。資料は「プロダクトが何を解決するか / 何を勝ちとするか」を記載する。

書式の正本は [FORMAT_UX.md](../../FORMAT_UX.md)。個別内容の正本は対象プロダクトの
`spec/ux/`。ドメイン定義・画面仕様・実装計画と別の責務として維持する。
読み取り側の契約は [共通参照仕様](../interface/core-domain-ux-consumers.md)。

参照サンプルは [examples/core-domain-task](../../examples/core-domain-task/README.md)。
タスク完了の UX → 業務不変条件 → 述語 → 呼び出し観測 → 版付き受け入れ判定を示す。
これは自己完結した同期 Node.js サンプルであり、Cc 本番や Augur/Lapilli の公開 API の
実装済み証明には使わない。サンプルの人工的な承認も実プロダクトの承認には使えない。

## 受け入れ条件

- 書式は対象利用者・問題・プロダクトの勝ち・コアドメインの貢献・制約を別々に記載できる。
- Anatomia/Praeforma は同じ文書 ID / リポジトリ / パス / 内容ハッシュで文書を参照する。
- サンプルでは不足条件を持つタスクを完了させず、入力状態を変更しない。
- 契約欠落・未観測・異なるコード版/契約版/実行の証跡・観測不能は受け入れを拒否する。
- 同じ版の違反は保持し、修正後は別の検証実行として判定する。
- 実行しなかった検証は成功として報告しない。

## 検証の扱い

`examples/core-domain-task/test/` に正常・異常・故障・証跡の取り違えを確認するテストを同梱。
本変更のセッションではユーザー指示に従い実行しない。手順と期待値はサンプル README に記載する。
