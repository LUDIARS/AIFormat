## 1. パフォーマンス・ベンチマーク (Performance & Benchmark)

性能要求が定義され、計測され、回帰検出される仕組みがあるかを評価する。

| 評価 | 観点 | 所見 |
|------|------|------|
| A~D | パフォーマンス要件の明文化 | |
| A~D | ベンチマーク・負荷試験 | |
| A~D | プロファイリング (CPU / メモリ / I/O) | |
| A~D | 性能リグレッション検知 | |
| A~D | 高負荷・大規模データ時の挙動 | |

### チェック項目

- [ ] レイテンシ (p50/p95/p99)・スループット・エラー率の目標値が文書化されているか
- [ ] 負荷試験・ベンチマークが存在し、CI または定期実行されているか
- [ ] ホットパス・スロークエリがプロファイリングで特定されているか
- [ ] リグレッションを CI で自動検出する仕組みがあるか
- [ ] 大量データ・大量同時接続時の挙動が検証されているか
- [ ] メモリリーク・コネクションリーク・FD リークが起きないことが確認されているか
- [ ] キャッシュ戦略 (CDN / アプリ / DB) が必要箇所で導入されているか
- [ ] cold start / オートスケール時の立ち上がりが許容範囲か

## 2. クロスプラットフォーム互換 (Cross-Platform Compatibility)

サーバランタイムおよびフロントエンド実行環境の互換性を評価する。

| 評価 | 観点 | 所見 |
|------|------|------|
| A~D | サーバランタイム / OS 差 | |
| A~D | ブラウザ互換 (フロントエンド) | |
| A~D | 文字エンコーディング・タイムゾーン | |
| A~D | コンテナ・ビルド再現性 | |
| A~D | CI でのマトリクス実行 | |

### チェック項目

- [ ] サーバが想定する OS / ランタイムバージョンが固定・文書化されているか
- [ ] フロントエンドが対象ブラウザ・バージョンで動作確認されているか
- [ ] 文字エンコーディング (UTF-8)・改行・タイムゾーン (UTC基準) の扱いが統一されているか
- [ ] コンテナイメージのビルドが再現可能か (lock ファイル / pinned base image)
- [ ] パスを `/` ハードコードせず OS 非依存に組み立てているか
- [ ] CI がサーバランタイム / ブラウザのマトリクスで実行されるか
- [ ] arm64 / x86_64 等のアーキテクチャ差が考慮されているか

## 3. アクセシビリティ・国際化 (Accessibility & i18n) ※フロントエンドがある場合

| 評価 | 観点 | 所見 |
|------|------|------|
| A~D | キーボード操作 | |
| A~D | セマンティクス / 支援技術対応 | |
| A~D | 視認性 (コントラスト / フォーカス) | |
| A~D | 国際化 (i18n) | |

### チェック項目

- [ ] 主要ユーザーフローがキーボードのみで完了できるか
- [ ] 画像 alt / フォームラベル / 見出し・ランドマーク等のセマンティクスが整備されているか（WCAG の準拠目標が明示されているか）
- [ ] コントラスト比・フォーカス表示・拡大時のレイアウトが確保されているか
- [ ] 自動 a11y チェック（axe 等）またはスクリーンリーダーでの主要フロー確認が CI / QA に組み込まれているか
- [ ] UI 文言がハードコードされず i18n 機構経由か（対象ロケールが定義されているか）
- [ ] 日付・数値・通貨・タイムゾーンの表示がロケールに応じて整形されているか

> Web フロントエンドを持たない純 API サーバは本項目を「対象外」とする。

**評価基準**（重大度の定義・導出ルール・対象外の扱いは [REVIEW.md「評価の決定ルール」](../REVIEW.md#評価の決定ルール) を正本とする）:
- **A**: 指摘 0 件。チェック項目をすべて満たす
- **B**: Medium / Low の指摘のみ。運用上の影響は低い
- **C**: High の指摘が 1 件以上。リリース前の対応を推奨
- **D**: Critical の指摘が 1 件以上。即時対応が必要
