## 1. データスキーマの妥当性・重複確認 (Data Schema Validation)

データモデル・スキーマ定義の妥当性と重複を検証する。

| テーブル / モデル | 問題種別 | 説明 | 推奨対応 |
|-----------------|---------|------|---------|
| | 正規化不足 / 重複 / 型不整合 / 制約不足 | | |

### チェック項目

- [ ] 正規化が適切に行われているか (不要な冗長データがないか)
- [ ] 同一概念を表す複数のモデル定義が存在しないか
- [ ] フィールドの型が格納データに対して適切か
- [ ] NOT NULL・UNIQUE・外部キー等の制約が必要十分に設定されているか
- [ ] インデックスがクエリパターンに対して最適化されているか
- [ ] マイグレーションに破壊的変更 (カラム削除等) が含まれていないか
- [ ] API のリクエスト/レスポンス定義とDBスキーマの間に矛盾がないか
- [ ] Enum・定数の定義がコードとスキーマで一致しているか
- [ ] N+1 クエリを誘発するスキーマ・関連定義になっていないか

## 2. SRE観点のレビュー (SRE Review)

運用・信頼性の観点でシステムを評価する。

| 評価 | 観点 | 所見 |
|------|------|------|
| A~D | 可観測性 (Observability) | |
| A~D | デプロイ安全性 | |
| A~D | スケーラビリティ | |
| A~D | 障害復旧 (Disaster Recovery) | |
| A~D | 依存関係管理 | |

### チェック項目

- [ ] 構造化ログが出力されているか (トレースID, リクエストID の付与)
- [ ] メトリクス収集 (レイテンシ, エラー率, スループット) が実装されているか
- [ ] ヘルスチェックエンドポイントが存在するか (liveness / readiness)
- [ ] デプロイがロールバック可能か
- [ ] 設定変更が再デプロイなしで反映可能か
- [ ] リソース制限 (CPU / メモリ / コネクションプール) が設定されているか
- [ ] 水平スケーリングに対応した設計か (ステートレス, 分散ロック等)
- [ ] バックアップ・リストア手順が確立されているか
- [ ] SLI / SLO が定義されているか
- [ ] インシデント発生時のランブックが存在するか
