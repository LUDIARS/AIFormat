### チェック項目

- [ ] マジックナンバー・マジックストリングが使用されていないか
- [ ] 過度にネストした条件分岐がないか (早期リターンで改善可能か)
- [ ] 未使用のコード・デッドコードが残存していないか
- [ ] コピー&ペーストによる重複コードがないか (DRY違反)
- [ ] 変数・関数のスコープが必要以上に広くないか
- [ ] 例外の握りつぶし (空の catch ブロック) がないか
- [ ] 不適切な型変換・暗黙的型変換がないか
- [ ] ログ出力が適切なレベルで記録されているか
- [ ] 命名が役割を正しく表しているか
- [ ] 関数・メソッドが過度に長大化していないか (長い場合、複数責務が混ざっていないか、RULE_CODE §2)
- [ ] クラス / モジュール / 関数が単一責任を守っているか (God Class が無いか、RULE_CODE §1)
- [ ] 1 ファイル 1 責務になっているか・複数責務が同居していないか (分割判断は行数でなく責任。単一責任なら大きくても可、RULE_CODE §2)
- [ ] レイヤー依存方向が一方向か (下層が上層を import していないか、RULE_CODE §3)
- [ ] 例外の握りつぶしに理由コメントがあるか (best-effort swallow の明示、RULE_CODE §7)
