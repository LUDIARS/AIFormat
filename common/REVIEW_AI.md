# AI 活用レビュー（共通） (AI Usage Review — Common)

全スタイル共通。LLM 機能を組み込んだプロダクトのセキュリティと、AI が生成したコードの検収状態を評価する。

> - **観点 1 (LLM 機能のセキュリティ)** は、プロダクトが LLM 機能（チャット / 要約 / 検索補助 /
>   エージェント / 生成系機能等）を持たない場合「対象外」とする。
> - **観点 2 (AI 生成コードの検収)** は、AI 支援で開発しているすべてのリポジトリに適用する。
> - AI 生成コードの取り込みに関する**ライセンス方針**は [REVIEW_QUALITY.md §2](REVIEW_QUALITY.md) で確認する。

## 1. LLM 機能のセキュリティ (LLM Feature Security)

プロダクトに組み込まれた LLM 機能の信頼境界とデータの流れを評価する。

| 重大度 | 該当箇所 | 種別 | 説明 | 推奨対応 |
|--------|----------|------|------|----------|
| Critical / High / Medium / Low | `file:line` | | | |

### チェック項目

- [ ] プロンプトインジェクション: 外部由来コンテンツ（ユーザー入力 / Web / ドキュメント / ツール実行結果）を、システム指示と分離・明示せずにプロンプトへ混ぜていないか
- [ ] LLM 出力を検証なしに信頼境界の内側で使っていないか（SQL / シェル / HTML 描画 / コード実行 / ファイルパスへの直挿し）
- [ ] ツール呼び出し（function calling / エージェント）の権限が最小限か。破壊的・外向きの操作に確認ゲートがあるか
- [ ] 個人データ・secret をプロンプトとして外部 API に送っていないか（送る場合、送信先・目的が規約とプライバシーポリシーに明記されているか）
- [ ] プロンプト・応答のログに機微情報が残らないか（マスキング・保持期間）
- [ ] コスト・レート暴走への上限があるか（トークン上限 / 呼び出し回数制限 / タイムアウト / 再帰・ループの打ち切り）
- [ ] モデル・プロンプトの変更が管理され、出力品質の回帰を検知する評価（eval / ゴールデンセット）があるか

## 2. AI 生成コードの検収 (AI-Generated Code Acceptance)

AI が生成したコードが検収なしに取り込まれていないか、検収の仕組みが機能しているかを評価する。

| 該当箇所 | 問題分類 | 説明 | 推奨修正 |
|----------|---------|------|---------|
| `file:line` | | | |

### チェック項目

- [ ] 幻覚 API・存在しない依存・存在しないオプションが混入していないか（ビルド / 型検査 / テストが検収として機能しているか）
- [ ] 指示範囲外の「ついで実装」・便利スクリプトが混入していないか（スコープの膨張。HARNESS §3.2）
- [ ] 既存ユーティリティ・既存パターンを無視した再実装がないか（[REVIEW_DESIGN.md §2](REVIEW_DESIGN.md) と併せて確認）
- [ ] 実質的に検証しないテスト（アサーション無し / モックの自作自演 / 実経路を通らない）で green を装っていないか（HARNESS §3.4）
- [ ] 過剰な防御・過剰な抽象化・使われない設定可能性が持ち込まれていないか
- [ ] AI 生成コードの検収手順（人間または上位モデルによるレビュー / 実経路での裏取り）がプロジェクトとして定義・運用されているか

**評価基準**（重大度の定義・導出ルール・対象外の扱いは [REVIEW.md「評価の決定ルール」](../REVIEW.md#評価の決定ルール) を正本とする）:
- **A**: 指摘 0 件。チェック項目をすべて満たす
- **B**: Medium / Low の指摘のみ。運用上の影響は低い
- **C**: High の指摘が 1 件以上。リリース前の対応を推奨
- **D**: Critical の指摘が 1 件以上。即時対応が必要
