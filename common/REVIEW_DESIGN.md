## 0. ドメイン紐づけ (Domain Alignment)

**設計レビューはここから入る。** ドメインは設計時点で決まるため、
「この変更がどのドメインのものか」が答えられない設計は、以降の項目を見る前に戻す。
判定は Anatomia のドメイン定義(正本: `spec/domains/`)を根拠とする。

| 変更範囲 | 着地ドメイン | 宣言の有無 | 所見 |
|----------|--------------|-----------|------|
| `path/` | | 既存 / 本 PR で追加 / **未宣言** | |

### チェック項目

- [ ] 変更・新規実装がどのドメインに属するかを、設計文書が明示しているか
- [ ] 新設ディレクトリ・新機能面が **同じ PR で** ドメイン登録されているか
      (`spec/domains/<name>.domain.json` 新規、または既存 `membership` へ `pathPattern` 追加)
- [ ] `membership` に src だけでなく tests も含めているか
- [ ] ドメイン JSON が parse でき、`pathPattern` が正規表現として妥当か
      (壊れていても警告なく無視され、未宣言と同じ症状になる)
- [ ] 1 つの変更が複数ドメインにまたがっていないか。またがるなら境界が正しいか
- [ ] 既存ドメインの守備範囲に収まるものを、不必要に新ドメインとして切っていないか
- [ ] ディレクトリ構成・モジュール境界が宣言したドメイン境界と一致しているか
- [ ] `anatomia verify` が pass するか(exit 0)。所見(orphan / coupling_delta 等)に対応があるか

## 1. 設計強度 (Design Robustness)

アーキテクチャおよび設計の堅牢性を評価する。

| 評価 | 観点 | 所見 |
|------|------|------|
| A~D | 障害分離 | |
| A~D | 冪等性 | |
| A~D | 入力バリデーション | |
| A~D | エラーハンドリング | |
| A~D | リトライ・タイムアウト設計 | |
| A~D | 状態管理の明確性 | |

### チェック項目

- [ ] 単一障害点 (SPOF) が存在しないか
- [ ] 外部サービス・外部リソース障害時の縮退動作が定義されているか
- [ ] 入力値の境界値・異常値に対する防御が十分か
- [ ] エラー発生時にシステムが安全な状態に遷移するか (fail-safe)
- [ ] 非同期処理のタイムアウトとキャンセル機構があるか
- [ ] 競合状態 (race condition) のリスクが排除されているか

## 2. 設計思想の一貫性 (Design Philosophy Compliance)

プロジェクトの設計思想・規約から逸脱しているコードを検出する。

| 該当箇所 | 逸脱内容 | 本来の設計思想 | 推奨修正 |
|----------|---------|--------------|---------|
| `file:line` | | | |

### チェック項目

- [ ] レイヤー間の依存方向が規約通りか (例: domain → infrastructure の依存がないか)
- [ ] 命名規則がプロジェクト全体で統一されているか
- [ ] 共通パターン (リポジトリパターン, サービス層等) が一貫して適用されているか
- [ ] 既存のユーティリティ・ヘルパーを無視した再実装がないか
- [ ] 責務の配置がアーキテクチャの意図と合致しているか
- [ ] 設定値のハードコーディングがないか (環境変数・設定ファイルに外出しすべき値)

## 3. モジュール分割度 / 機能的凝集度 (Cohesion & Modularity)

各モジュールが単一の責務に集中しているかを評価する。

| モジュール / クラス | 凝集度評価 | 所見 |
|-------------------|-----------|------|
| | 機能的 / 逐次的 / 通信的 / 手続き的 / 時間的 / 論理的 / 偶発的 | |

### チェック項目

- [ ] 1つのクラス・モジュールが複数の無関係な責務を持っていないか (SRP違反)
- [ ] God Object / God Class が存在しないか
- [ ] 結合度が不必要に高くないか (変更の影響範囲が広すぎないか)
- [ ] 循環依存が発生していないか
- [ ] インターフェースが適切に分離されているか (ISP)
- [ ] パッケージ・ディレクトリ構成がドメインの構造を反映しているか

**評価基準**（重大度の定義・導出ルール・対象外の扱いは [REVIEW.md「評価の決定ルール」](../REVIEW.md#評価の決定ルール) を正本とする）:
- **A**: 指摘 0 件。チェック項目をすべて満たす
- **B**: Medium / Low の指摘のみ。運用上の影響は低い
- **C**: High の指摘が 1 件以上。リリース前の対応を推奨
- **D**: Critical の指摘が 1 件以上。即時対応が必要
