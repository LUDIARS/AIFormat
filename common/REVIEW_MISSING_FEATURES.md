## 1. 機能の改善提案 (Feature Improvement)

既存機能の改善案を提案する。

| 対象機能 | 改善提案 | 期待効果 | 優先度 |
|---------|---------|---------|--------|
| | | | High / Medium / Low |

### 観点

- パフォーマンス最適化 (不要な計算, キャッシュ活用, I/O 削減)
- ユーザ体験の向上 (レスポンス速度, エラーメッセージの改善)
- テスタビリティの向上 (依存注入, モック可能性)
- 運用負荷の軽減 (自動化, 設定の簡素化)

---

## 2. 不足機能の提案 (Missing Feature Proposal)

現在の実装に対して追加すべき機能を提案する。

| 提案機能 | 必要性の根拠 | 実装優先度 | 想定影響範囲 |
|---------|------------|-----------|------------|
| | | High / Medium / Low | |

### 観点

- 入力バリデーションの不足
- エラー通知・アラートの欠如
- 監査ログの不足
- 死活監視・自己診断の未実装
- レート制限・スロットリングの未実装
- バッチ処理・リトライ機構の不足
- ドキュメント・仕様の不足

## 総合評価

| # | レビュー観点 | 指摘数 | 優先度別内訳 |
|---|------------|--------|------------|
| 1 | 機能改善 | | High: / Medium: / Low: |
| 2 | 不足機能 | | High: / Medium: / Low: |

**優先度基準:**
- **High**: 不具合・セキュリティ・データ保全・法令対応に直結する
- **Medium**: 品質・運用効率・開発速度を明確に改善する
- **Low**: 利便性・体験の向上に留まる

> 本ドキュメントの 2 観点は A〜D の評価軸を持たない（提案であり現状の欠陥指摘ではないため）。
> 総合評価表では評価を「-」とし、指摘数と優先度内訳のみ記載する。
