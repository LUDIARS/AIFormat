# タスク完了と受け入れ観測

- INV-1: 条件は非空で、一意な ID と boolean の met を持つ。全 met が true の時だけ completed。
- INV-2: 入力状態を正常・未達のどちらでも変更しない。戻り値の ID は入力と同じ。
- INV-3: 未達なら false の条件 ID を入力順に返す。空条件なら missing-criteria。
- INV-4: 型/形状の不正は TypeError で拒否する。不正入力へ業務結果を返すことは違反。

`completeTask` は同期の純粋なドメイン処理。観測・JSONL・git・時刻に依存しない。
`C-1` の述語は INV-1〜3 を独立した条件として検査し、実装関数自身を答え合わせに呼ばない。
観測ラッパーは呼び出し前スナップショットと後の引数を比較できる。

受け入れ側は `policy.json` の必須契約とシナリオを、観測される実装とは独立に保持する。
版は UX・契約・コード・ポリシーを含むサンプル全体の内容ハッシュ。runId は実行単位で生成する。
違反はその実行内で一件でもあれば拒否。現在版と別の実行のログは証拠に使わない。

本サンプルは書込みのないローカル検証例で、サービスを起動しない。
ルール強制の本番境界、ログへの署名、遠隔コレクター、非同期関数は対象外。
実サービスでは証跡収集器と承認ポリシーを実装エージェントの編集権限から分離すること。
