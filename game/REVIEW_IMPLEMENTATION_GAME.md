## 1. セーブデータ設計 (Save Data Design)

| 評価 | 観点 | 所見 |
|------|------|------|
| A~D | フォーマット・バージョニング | |
| A~D | 後方互換（旧データの読み込み） | |
| A~D | 破損耐性 | |
| A~D | クラウドセーブとの整合 | |

### チェック項目

- [ ] セーブデータのフォーマットとバージョンが管理されているか
- [ ] 旧バージョンのセーブデータを新バージョンで読み込めるか（マイグレーション）
- [ ] 書き込み中のクラッシュ・電源断でセーブが破損しないか（アトミック書き込み / 二重バッファ）
- [ ] オートセーブの頻度・タイミングが適切か（プレイ体験とのバランス）
- [ ] クラウドセーブとローカルセーブの競合解決が定義されているか
- [ ] 複数スロット・複数プロファイルの管理が破綻していないか

## 2. アセット・リソース管理 (Asset & Resource Management)

| 評価 | 観点 | 所見 |
|------|------|------|
| A~D | アセットパイプライン | |
| A~D | ロード / アンロード戦略 | |
| A~D | アセット参照の整合性 | |

### チェック項目

- [ ] アセットのインポート・ビルドパイプラインが自動化・再現可能か
- [ ] アセットの命名規則・参照（GUID / ID 等）が一貫しているか
- [ ] 動的ロード / アンロード・ストリーミングが適切に設計されているか
- [ ] アセットのバージョン・依存関係が管理され、壊れた参照（missing reference）がないか
- [ ] 未使用アセットがビルドに含まれていないか（ビルドサイズ）

---

## 3. データ駆動設計 (Data-Driven Design)

### チェック項目

- [ ] ゲームバランス値（パラメータ / テーブル）がコードから分離されているか
- [ ] マジックナンバーがハードコードされず設定データ化されているか
- [ ] ローカライズ文字列がコードから分離されているか
- [ ] デザイナーが触る値とエンジニアが触るコードの境界が明確か
- [ ] データの不正値・欠損に対するバリデーション・フォールバックがあるか

**評価基準**（重大度の定義・導出ルール・対象外の扱いは [REVIEW.md「評価の決定ルール」](../REVIEW.md#評価の決定ルール) を正本とする）:

- **B**: Medium / Low の指摘のみ。運用上の影響は低い

- **D**: Critical の指摘が 1 件以上。即時対応が必要
