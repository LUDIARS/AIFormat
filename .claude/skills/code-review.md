# コードレビュースキル

AIFormat ルール (RULE_TECH_STACK.md, 各プロジェクトの CLAUDE.md) に基づき、コードベースをレビューする。

## 実行タイミング

- ユーザーが `/code-review` と入力したとき
- 対象: カレントディレクトリのプロジェクト

## チェック項目

### 1. TypeScript 型安全性
- `any` 型の使用を検出（`catch (e: any)`, `useState<any>`, `request<any>` 等）
- 修正: `unknown` + 型ナローイング、または具体型の定義

### 2. Repository パターン
- ルートハンドラ / WS コマンドハンドラが `db` を直接インポートしていないか
- `src/db/repository.ts` のリポジトリ関数を経由しているか

### 3. フロントエンド・バックエンド整合性
- WS コマンドのフィールド名がバックエンドハンドラと一致しているか
- API レスポンス型がフロントエンドで正しく定義されているか

### 4. npm scripts クロスプラットフォーム
- `package.json` の scripts に bash 専用構文がないか
- 禁止: `&` バックグラウンド, シングルクォート, `cd &&`, `$(cmd)`, `export`, `source`

### 5. 未使用コード
- 未使用の import
- 到達不能コード

### 6. セキュリティ
- OWASP Top 10 (XSS, SQL Injection, etc.)
- パストラバーサル防止

## 出力フォーマット

| 重要度 | ファイル:行 | ルール | 説明 | 修正案 |
|--------|-----------|--------|------|--------|
| error | path:line | rule | desc | fix |

## 修正フロー

1. レビュー結果を報告
2. クリティカル（ランタイムバグ）を優先修正
3. ブランチを切ってコミット・PR
4. PR 本文に「Other findings」として残りの課題を記載
