## 1. LLM 機能のセキュリティ (LLM Feature Security)

**対象外**: AIFormat はレビューフォーマット・規約・CI ゲートスクリプト・Claude Code 向けプロンプト/スキルを配布する
governance リポジトリであり、実行時に LLM API を呼び出すプロダクト機能を持たない。`scripts/*.mjs` の import は
全て `node:*` builtin のみ (前掲 `REVIEW_CODE_QUALITY.md` §1 で確認済み) で LLM SDK 等への依存も無い。
`prompt/*.md` (`REVIEW_FULL.md` / `REVIEW_PR.md` / `SPEC_GAP.md`) は外部の AI エージェント (Claude Code 等) に
与えるテキスト指示であり、本リポジトリ自体が信頼境界を持つ LLM 機能を実行しているわけではないため、
本節のチェック項目 (プロンプトインジェクション / 出力の信頼境界越境利用 / ツール呼び出し権限等) は対象外とする。

### チェック項目

- [x] プロンプトインジェクション — 対象外 (LLM 機能なし)
- [x] LLM 出力を検証なしに信頼境界の内側で使っていないか — 対象外
- [x] ツール呼び出し（function calling / エージェント）の権限が最小限か — 対象外
- [x] 個人データ・secret をプロンプトとして外部 API に送っていないか — 対象外
- [x] プロンプト・応答のログに機微情報が残らないか — 対象外
- [x] コスト・レート暴走への上限があるか — 対象外
- [x] モデル・プロンプトの変更が管理され、出力品質の回帰を検知する評価があるか — 対象外

## 2. AI 生成コードの検収 (AI-Generated Code Acceptance)

AI が生成したコードが検収なしに取り込まれていないか、検収の仕組みが機能しているかを評価する。

| 該当箇所 | 問題分類 | 説明 | 推奨修正 |
|----------|---------|------|---------|
| `HARNESS.md:183-191` (§3.6 完了の定義) と `scripts/` (テスト0件) | 方針と実態の乖離 | `HARNESS.md` §3.6 は「テストが green」であることを AI 実装の完了条件として明記しているが、AIFormat 自身の `scripts/*.mjs` にはテストが 1 件も存在しない (`REVIEW_QUALITY.md` QUALITY-001 と同一事実)。文書化された検収基準が、当のリポジトリ自身の成果物には適用できていない状態にある | `scripts/*.mjs` に `node:test` 等で最低限のテストを追加し、§3.6 の完了条件を自己適用できる状態にする |

### チェック項目

- [x] 幻覚 API・存在しない依存・存在しないオプションが混入していないか — `scripts/*.mjs` 全 14 本を全文読了した範囲では `node:*` builtin API の誤用・存在しないオプションは確認されなかった。ただしビルド/型検査/テストが検収として機能していない点は右記の指摘に計上 |
- [x] 指示範囲外の「ついで実装」・便利スクリプトが混入していないか — 各スクリプトは JSDoc の Usage と実装が 1 対 1 で対応しており、スコープ膨張の痕跡は確認されず
- [x] 既存ユーティリティ・既存パターンを無視した再実装がないか — `REVIEW_DESIGN.md` で確認済み。重大な無視した再実装は無し (`sync.sh`/`sync-local.sh` の重複は「既存を無視した別実装」ではなく単純な複製であり DESIGN-002 で計上)
- [x] 実質的に検証しないテスト（アサーション無し等）で green を装っていないか — テスト自体が存在しないため「偽装された green」は無い (テストが 0 件という事実は QUALITY-001 で計上済み。本項目は「存在するテストが空虚か」を問うものであり該当なし)
- [x] 過剰な防御・過剰な抽象化・使われない設定可能性が持ち込まれていないか — `env-leak-checker.mjs` の `--ext` 引数等、オプションはいずれも実際に使用されており過剰な設定可能性は確認されず
- [ ] AI 生成コードの検収手順（人間または上位モデルによるレビュー / 実経路での裏取り）がプロジェクトとして定義・運用されているか — `HARNESS.md` §3.4/§3.6 に手順は定義されているが、自リポジトリへの適用が不十分 (上表 AI-002)
